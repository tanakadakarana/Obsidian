## バイブコーディング初心者のための Skills(スキル)入門

[伊藤貴將（いとうたかまさ、イトパン）｜安曇むすひ](https://note.com/azumimusuhi)

どうも、イトパンです。  
まずニュースから。

Cowork（コワーク） が、ClaudeのmacOSアプリで「研究プレビュー」として公開されました。（出典: Anthropic公式ブログ 2026-01-12）  
  
位置づけはシンプルで、 **“非エンジニア向けのClaude Code”** 。  
「Claude Codeの仕組みを、非コーディング作業に寄せたもの」として紹介されています。

利用条件も大事なので先に言うと。  
現時点では **Claude Max加入者向け** （※Max以外は待機リストあり）で、 **macOSアプリ内** で使える形です。  
Max加入者はかなりコアだと思うので、本当の非エンジニア層に届くのはもう少し先かも。  
  
※1/17日にProプランまで使えるようになりました。  
よかったらこちらもどうぞ👇

だから逆に、チャンスです。  
Coworkが一般利用に届く前の今は、 **スキル（型）を練習する期間** にできる。  
かつ、ClaudeCodeも触ってみよう。

Coworkが何をするかというと、だいたいこの3つ。

- あなたが選んだフォルダにだけアクセスさせる
- その中で「読む / 作る / 編集する」をやらせる
- タスクは計画を立てて、進捗を知らせながら進める（代理作業っぽい）

さらに、複数タスクをキューに積んで回す発想も入っています。

たとえば。  
ダウンロードの整理、領収書スクショから経費表、散らばったメモからレポート草案。

…ここまで聞くと最高。  
ただし、注意点もある。

Coworkはフォルダに触れます。  
指示が曖昧だと、削除などの破壊的操作につながり得る。  
なので公式も「明確に指示してね」と注意しています。（出典: Anthropic公式ブログ）

そこで今日のテーマはこれです。

✅ **バイブは残す。でも結果はブレさせない**

![画像](https://assets.st-note.com/img/1768311480-UkrYKv3MG72j5DZEAhgI6lb8.png?width=1200)

Coworkが広く使えるようになったとき。  
そのまま仕事に使える “型” を、先に作っておこう。

バイブコーディングって、「こういう感じのやつ作りたい」みたいな“熱”を会話で形にしていくスタイル。  
気持ちよさはあるけど、弱点は1つ。  
**毎回ちょっとずつ違う。**

そこで出てくるのが Skills（スキル）。  
Skillsは一言でいうと、 **作業のレシピを保存しておく仕組み** です。（出典: OpenAI Codex Skills docs）

- いつ使う？（発動条件）
- どういう順番でやる？
- 出力はどの形？
- どこは触っちゃダメ？
- 重要操作はいつ確認する？

ここを固定すると。  
バイブの“勢い”と、仕事の“再現性”を両立できます。

## 1) Skillsの正体：フォルダ丸ごと「レシピ箱」📦

![画像](https://assets.st-note.com/img/1768311520-78Ykrig4yIdeQuqvS9XDFxAo.png?width=1200)

Skillsは「1枚のプロンプト」じゃなく、手順・テンプレ・追加資料をまとめた“フォルダ”として設計すると強いです。

Claude Code の中心は SKILL.md。  
思想は Progressive Disclosure（段階的読み込み）。

- 起動時: 全スキルの name / description だけ読む
- 発動時: 必要なスキルの SKILL.md 本文を読む（確認が入る）
- 必要時: scripts/ や references/ の追加資料を読む

初心者が最初に覚えるコツはこれだけでOK。  
description に「いつ使うか」を書く。  
ここが曖昧だと、AIが「そのレシピを出すタイミング」を判断できません。

※CoworkはSKILL.mdでスキルを作る方式ではなく、フォルダを許可して“代理作業”させるアプリ機能。発想は近いけど仕組みは別です。

保存場所は2択。

- 自分用：~/.claude/skills/（まずはここが安全）
- チーム共有：.claude/skills/（運用が固まったら強い）

## 2) Coworkを非エンジニアが使うなら、まず「型」を握る

![画像](https://assets.st-note.com/img/1768311545-Ia4zhRAZiJCfPvYKdGMBO6El.png?width=1200)

Coworkは便利そうです。  
でも便利な道具ほど、取り扱い説明書が必要。

🧯 **安全運転の3ステップ（ここだけ固定）**

1. まずは「整理案だけ」出させる（実行しない）
2. あなたがOKを出したら実行
3. 最後にログを残す（何をどこへ動かしたか）

Coworkは「明示的に許可したフォルダだけ」触れる設計です。（出典: Anthropic公式ブログ）  
とはいえ誤解釈リスクはゼロじゃないので、こちらが“型”で守ります。

✅ Coworkに投げるプロンプト（コピペ用）

### ① ファイル整理（ダウンロード/納品データ/写真）

```
このフォルダを整理したい。
最初に「整理案（フォルダ構成とリネーム規則）」だけ出して。実行はしないで。
OKを出したら、その案で実行して、最後に「移動ログ」を1ファイルにまとめて。
```

### ② 領収書スクショ → 経費表

```
このフォルダのスクショを見て、日付/金額/店名/カテゴリ/備考 の表にして。
まずは「サンプル10件」だけ作って、列が合ってるか確認させて。
不明は needs_review に入れて。
```

### ③ 散らばったメモ → レポート草案

```
このフォルダのメモを統合して、結論→根拠→次のアクションの順で1枚にまとめて。
不明点は最後に「質問3つ」だけ出して。
```

## 3) Claude Code版：非エンジニアの「型」をルールとして残す

![画像](https://assets.st-note.com/img/1768311580-HDq3a4mgvpfBdhXcJClTNL2E.png?width=1200)

Coworkでうまくいった“やり方”。  
これ、毎回コピペするのはしんどいです。

なので次は「型を保存する」パート。

Claude Code側は、ルール（メモリ）を \`.claude/\` に置いて育てられます。（出典: Claude Code docs: Memory management）

覚えるのは2つだけ。

- **チーム共有（このリポジトリだけ）**: \`./.claude/CLAUDE.md\` と \`./.claude/rules/\*.md\`（または \`./CLAUDE.md\`）（出典: Claude Code docs: Memory management）
- **自分専用（全プロジェクト）**: \`~/.claude/CLAUDE.md\` と \`~/.claude/rules/\`（出典: Claude Code docs: Memory management）

やることも2つ。

1. まず “守る型” を文章にする
2. 必要なら \`paths\` で「この範囲だけ」効かせる

### 例：ファイル整理ルール（そのままコピペでOK）

\`.claude/rules/file-organizing.md\` のイメージ。（出典: Claude Code docs: Memory management）

```cpp
---
paths:
  - "docs/inbox/**"
  - "Downloads/**"
---
- いきなり移動/削除しない
- まず「整理案（フォルダ構成案＋命名規則）」だけ出す
- ユーザーのOKが出てから実行
- 最後に log.md を作り、moved / renamed / keep を残す
```

ポイントは。  
**“やること”より、“やっちゃダメ”を先に固定** です。

そして、運用しながら \`/memory\` で育てられます。（出典: Claude Code docs: Memory management）

### 例：領収書スクショ → 経費表ルール（そのままコピペでOK）

\`.claude/rules/receipts-to-expenses.md\` のイメージ。

```javascript
---
paths:
  - "receipts/**"
  - "expenses/**"
---
- まずファイル一覧を作って、重複/不鮮明をマークする
- 最初は「サンプル10件」だけ表にして、列が合ってるか確認する
- 全件の表では、不明は needs_review に入れる
- 最後に「合計」と「カテゴリ別合計」を出す（推測は分けて書く）
```

### 例：散らばったメモ → 1枚ブリーフ（そのままコピペでOK）

\`.claude/rules/notes-to-brief.md\` のイメージ。

```javascript
---
paths:
  - "notes/**"
---
- 出力は1枚に収める（結論→根拠→次のアクション）
- 固有名詞は元メモから引用し、勝手に増やさない
- 不明点は最後に「質問3つ」だけ
```

## 4) Codex版Skills：作業の型をSKILL.mdで保存する

![画像](https://assets.st-note.com/img/1768311613-pSfzg7XjkBY4Pcmh905RArtJ.png?width=1200)

最後にCodex側。

Codex Skills は \`SKILL.md\` で「作業の型」を保存して、必要なときに呼び出せます。（出典: OpenAI Codex Skills docs）

### 置き場所（初心者は2つだけ）

- リポジトリ共有：\`$REPO\_ROOT/.codex/skills/\`
- 自分用：\`~/.codex/skills/\`

### ひな形（非エンジニアのファイル整理向け）

最小は \`name\` と \`description\` だけ。  
ただ、実務では “中身（安全ルールと出力の型）” まで書いておくと安定します。

```python
---
name: file-tidy-nontech
description: ダウンロード/納品/写真/領収書など、フォルダ整理を頼まれたときに使う。最初に整理案を出し、承認後に実行し、最後にログを残す
---

# File Tidy（非エンジニア向け）

## 絶対ルール（安全）
- いきなり移動/削除しない
- まず「整理案（フォルダ構成案＋命名規則）」だけ出す
- ユーザーのOKが出てから実行
- 最後に log.md を作り、実行内容を残す

## 整理の基本方針
1. 種類で分ける：images / pdf / docs / video / other
2. 日付が分かるものは YYYY-MM に寄せる
3. 命名規則：YYYY-MM-DD_内容_元名（例：2026-01-13_receipt_coffee.png）
4. 不明なものは needs_review に退避して、一覧で質問する

## 出力フォーマット（最初の返信）
- 目的（1行）
- 整理案（フォルダツリー）
- 命名規則（例つき）
- 確認したいこと（最大5つ）
```

ここでもコツは同じ。  
\`description\` に「いつ使うか（その言い回し）」を書く。

初心者はまず「明示呼び出し」（例: \`$file-tidy-nontech\`）が安心です。

### 作り方は2ルートです。

1. **いちばん簡単** ：組み込みの \`$skill-creator\` に作りたい内容を話す
2. **手動** ：フォルダを作って \`SKILL.md\` を置く

外部スキルを入れたら、Codexは再起動が必要です。

あと、チーム運用で「この場所の作法」を固めたいなら、AGENTS.mdも相性がいいです。

## ✅ まとめ：Coworkが一般利用に届く前にやる3つ

![画像](https://assets.st-note.com/img/1768311683-ERJmTB5vuGf2HrdxFt4CA7nI.png?width=1200)

- ✅ まとめ：Skillsの要点（復習）
	- Skillsは「作業のレシピ箱」：手順/出力/禁止/確認まで保存する
	- 発動のカギは \`description\`：「いつ使うか」を、ユーザーが言いそうな言葉で書く
	- 安全の型は「案→承認→実行→ログ」：Coworkみたいにフォルダを触る作業ほど効く
	- 保存先は2択：チーム共有（リポジトリ）/自分用（ユーザー）。まず共有に置くと育てやすい
